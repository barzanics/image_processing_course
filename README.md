# Image Processing with Python - a beginner-friendly course

Learn **image processing with Python (OpenCV + matplotlib + NumPy)** by building a program that:

- **(A)** reads English **letters** from an image,
- **(B)** reads English **digits** and converts them into real integers (the pixels `4 2 7` become the number `427`),
- **(C)** **detects** specific objects (by colour and by shape) and **crops** them out,
- **(D)** extracts **every digit** in a photo-like image and rebuilds the numbers.

Written for university students with little or no Python experience. Every notebook explains each code cell in plain language (*what this code does*, then *what you should see / why we care*), so a teacher can run it **cell by cell**.

The core course uses **only NumPy, OpenCV, matplotlib and Jupyter**. No OCR library, no machine learning, no downloads: all pictures are generated by `make_assets.py`.

## Install and run (copy-paste)

```bash
python -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python make_assets.py
jupyter notebook
```

Then open the `notebooks/` folder and start with `01_images_are_numbers.ipynb`. Run a cell with **Shift + Enter**.

## How to swap in your own image

Every notebook has one line near the top:

```python
IMAGE_PATH = "../assets/digits_grid_photo_like.png"
```

Put your photo in `assets/incoming/` (for example `myimage.png`) and change that one line to `"../assets/incoming/myimage.png"`. Rerun the cells. Works best with dark digits or letters, a plain font, upright text and fairly even light; see "where this would fail" in Notebook 08.

## Troubleshooting

- **The image looks blue / colours are wrong.** OpenCV stores pixels as BGR, matplotlib expects RGB. Convert with `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` (our `show()` does it for you). Explained in Notebook 01.
- **`cv2.imshow` freezes or shows nothing in Jupyter.** Do not use it in notebooks. Use `plt.imshow` (or our `show()`).
- **`findContours` returns 2 values vs 3.** OpenCV **4** returns **2** values (`contours, hierarchy`). Old OpenCV **3** returned **3** (`image, contours, hierarchy`). If you see `too many/not enough values to unpack`, check `cv2.__version__` and upgrade with `pip install -U opencv-python`.
- **`ModuleNotFoundError` (cv2, numpy, utils...).** You are probably in the wrong environment: activate the `.venv` and start Jupyter from it. For `utils` / `matcher`, keep the notebooks in their folder (they add `..` to the path).
- **`FileNotFoundError: Could not read ...png`.** Run `python make_assets.py` once from the main folder.

## Choices I made where the brief was open (simplest option)

- **Skewed picture = 10 degrees**, not 7. At 7 degrees the letters were still read correctly (only confidence dropped), so 10 degrees shows a visible error. Notebook 05 also tests 5, 7, 10 and 15 degrees.
- **"Several numbers in one picture"** are separated by a **gap rule** (a gap larger than 80% of a digit's height starts a new number), the simplest method that works.
- **Rows** in the capstone are found by sorting boxes by vertical centre and starting a new row at a jump of more than 40 px.
- **Template matching** compares crops and templates after squashing both to 32 x 32 with `TM_CCOEFF_NORMED`.
- **Extra images** beyond the required list: `digits_real_font.png` (a different font, to show where templates fail) and `assets/incoming/sample_numbers.png` (a practice picture for the final mini-project). Your own `myimage.png` is never overwritten.
- **`matcher.py`** is an extra file. Notebooks 05, 06 and 08 build the functions inline; only notebook 09 and the solutions import the finished versions.
- `findContours` is written for **OpenCV 4** (2 return values).
- Notebook 09 is the only one that mentions `pytesseract`, inside `try/except`, and it never breaks if it is missing.
